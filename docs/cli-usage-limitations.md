# CLI 操作與限制說明 (CLI Usage & Limitations)

本文件補充說明 PocketAgent CLI 介面在實際操作時的進階使用細節、邊界行為以及目前的系統限制。

## 附件與路徑解析

- **附加檔案**：可使用 `/file <完整路徑>` 附加一般檔案，路徑支援雙引號包覆。
- **行內引用**：在對話訊息內可使用 `@檔名` 或 `@路徑`。若路徑包含空白，必須加雙引號，例如：`@"D:\my project\說明.txt" 請幫我整理`。
- **剪貼簿快速貼上 (`Alt+V`)**：
  - **實體檔案複製**：支援從 Windows 檔案總管複製檔案後直接以 `Alt+V` 貼上為附件。
  - **記憶體截圖（免存檔）**：支援使用系統快捷鍵（如 Windows `Win+Shift+S`、macOS `Cmd+Ctrl+Shift+4`）截圖後，直接按下 `Alt+V` 自動擷取記憶體點陣圖、轉存為專屬暫存快取並登錄為待送附件，使用者無需手動另存實體檔案。
  - **去重防護**：內建 SHA-256 內容雜湊比對，連續多次貼上相同截圖會自動重用既有暫存檔案，避免產生重複檔案與重複待送項目。
  - **工作區授權豁免**：內部產生的截圖暫存檔自動具備內部信任，不會彈出干擾性的外部工作區權限請求。
- **讀取時機**：系統會對檔案路徑進行正規化與去重，並且**僅在送出訊息時**才會實際讀取內容。工具列上顯示的「待送 (Pending)」僅代表已加入佇列，不代表模型已經讀取。
- **清除行為**：
  - `/clear` 指令只會清除對話歷史，但會**保留**目前待送的附件。
  - 若要清空附件，請使用 `/attachments clear`。
- **目錄支援**：`/add-dir` 指令尚未完整接入，目前不會遞迴讀取目錄或擴大系統的工作權限。

## 會話管理與歷史切換 (Session Management)

- **全新會話 (`/new`)**：
  - 比照 Antigravity CLI (agy)，`/new` 會結束當前會話並開啟全新對話。
  - **自動保存防護**：若當前對話已有歷史紀錄，系統會在背後自動調用原子性存檔將前次會話寫入 `~/.pocket-agent/sessions/`，防止使用者工作成果遺失。
  - **100% 乾淨上下文**：除了換發全新的 `session_id` 外，會徹底清空 Agent 歷程記憶 (`history`)、待送附件佇列 (`pending_files`)、輸入失敗重試緩衝、Token 累積計數器、指令授權白名單以及生圖／產檔暫存。
  - **與 `/clear` 之差異**：`/clear` 僅清空記憶體中的對話歷史，但保留原有附件、授權狀態與相同的 Session ID；`/new` 則是全方位的會話重置（Fresh Session）。
- **對話重新命名 (`/rename`)**：
  - 用法：`/rename <新標題>` 或直接輸入 `/rename` 觸發互動式提示輸入。
  - 系統會將標題長度正規化（上限 60 字元），並自動更新 HMAC-SHA256 數位簽章後寫入磁碟。
  - 當日後執行 `/session` 叫出互動式光棒選單時，即可直觀看見清晰的會話主題，大幅提升檢索與重新載入歷史對話的效率。

## 子代理與平行路由 (Subagent Routing)

- **動態捷徑攔截**：當您使用 `/<子代理名稱>` (例如 `/researcher 查資料`) 或 `/subagent researcher 查資料` 時，系統會在 CLI 層級直接攔截指令，並直接在背景啟動子代理，而**不會讓主代理參與推論**。這能節省大量 Token，但這也意味著子代理**不知道**主對話歷史。
- **管線平行路由 (`/parallel`)**：
  - 用法：`/parallel researcher:任務A | coder:任務B`
  - 由於 CLI 原生解析機制的限制，請特別注意**必須使用直立的管線符號 `|`** 作為不同代理間的分隔，且各代理後方必須緊接冒號 `:` 加上任務內容。
  - **自動彙整 (Map-Reduce)**：本指令具備自動彙整功能。系統會在多個子代理各自完成任務後，於背景自動啟動一個輕量的「彙整者代理 (Summarizer)」，為您總結成一份清晰的最終報告，且完全不污染主代理的上下文記憶。
  - 提示：若您覺得符號難以記憶，也可以直接在對話框用自然語言向主代理說：「請派兩個子代理分別幫我做A與B並彙整」，主代理也會自行判斷並使用內建的平行工具完成相同的行為。

## 程式碼檢索與上下文注入 (Code Search)

- **隱式記憶寫入**：使用 `/codesearch <關鍵字>` (或 `/cs`) 檢索出的程式碼片段，會直接以背景假訊息的方式寫入對話歷史 (`agent.history`) 中。這意味著檢索結果會成為對話的長期記憶，並佔用當次會話的 Context Token。
- **本地執行無請求**：該指令的檢索過程與上下文注入完全在本機端 (SQLite FTS5) 瞬間完成，不會觸發對大語言模型的 API 請求。您可以連續執行多次 `/cs` 來收集多份不同檔案的片段，最後再統一對 AI 提問。

## 影像生成與模型限制

- **圖像生成**：`/image <描述>` 支援利用待送佇列中的附加檔案作為「參考圖」進行圖生圖 (Image-to-Image)。
- **提供者限制**：目前僅 `openai` 後端支援影像生成指令。
- **狀態管理**：透過 `/model` 指令進行的模型切換，**只對當次會話有效**，系統不會自動將其寫入全域設定檔中。

## 失敗、取消與交易限制 (核心限制)

- **自動還原**：當聊天或生圖過程中拋出例外錯誤時，系統會自動保留附件，並將原先的輸入文字預填回對話框供您修改，**不會自動重送**。
- **無交易回滾 (No Transaction Rollback)**：若執行中斷，本輪操作可能已經寫入了對話歷史或執行了部分外部工具 (Tools)。重送前請務必自行檢查執行結果。系統不提供核心交易回滾或 exactly-once 的執行保證。
- **狀態判定**：若核心引擎將錯誤包裝並轉為正常回覆，CLI 仍會將其視為成功並消耗本次附件。請勿僅依賴回覆的文字內容來猜測工具是否真正執行成功。
- **Shell 指令輸出與截斷**：當執行長時間運行或輸出龐大的 Shell 指令時，系統會對輸出進行動態分塊 (Chunking) 以保護記憶體，超過限制的部分將被截斷，並強制終止子進程。
- **中斷行為**：
  - `Ctrl+C` 的清空行為僅適用於「正在輸入」期間（會清空當前輸入框文字，但不會清除附件）。
  - 目前版本尚未完全接入「回答串流期間的安全取消 (Streaming Cancellation)」，在生成過程中強行中斷可能導致未預期的顯示狀態。

## 終端機渲染 (Terminal Rendering)

- **狀態顯示**：即使在無色彩輸出 (No-Color) 模式下，系統仍會提供文字狀態提示。
- **相容性**：在 Windows Terminal 的深色/淺色主題切換、多行文字貼上，以及終端機視窗極窄的情況下，排版可能不如預期，需由使用者人工檢視與適應。多行貼上時建議先將文字保留於外部編輯器中再貼入。

## 工作區沙盒與暫存生命週期 (Workspace Storage & Housekeeping)

- **專案目錄零污染 (Zero Project Pollution)**：
  借鑑 Claude Code 架構，執行期產生的所有暫存檔（Spillover 巨量日誌、剪貼簿截圖快取）與執行日誌（`agent.log`），一律收攏於全域家目錄中的工作區專屬沙盒：
  `~/.pocket-agent/workspaces/<workspace-slug>/`
  其中 `<workspace-slug>` 依據啟動時的工作區絕對路徑經過標準化轉換生成（例如 `D--_Personal-Repositories-Git-pocket-agent`）。專案目錄內絕不自動建立任何 `.agents/` 暫存資料夾。
- **管家維護機制 (Housekeeping)**：
  - **自動清理**：預設每 24 小時於啟動時自動檢查並淘汰超過 TTL（預設 7 天）或超出容量上限（預設 50 MB / 100 檔）的暫存日誌與過期截圖。
  - **手動清理**：可隨時於 CLI 輸入 `/clean` 指令，系統將對全域 `~/.pocket-agent/workspaces/` 下的所有工作區進行批次巡檢與空間釋放。
