# 圖解 BM25：搜尋結果為什麼這樣排序？

**BM25（Best Matching 25）是一種全文搜尋的相關性評分方法：用詞彙命中與統計特徵，決定文件的排序。它不是語意理解模型，分數也不是正確率或機率。**

## 1. 從查詢到排名

```text
查詢：「Python 非同步」
          │
          ▼
文字分析／斷詞 → [Python] [非同步]
          │
          ▼
透過倒排索引找出候選文件
（索引記錄哪些文件包含哪些詞）
          │
          ▼
對每份候選文件、每個查詢詞計分
          │
          ├─ 稀有程度：越少文件包含，通常越有辨識力
          ├─ 詞頻飽和：出現較多次會加分，但增益漸小
          └─ 長度調整：降低長文件天然容易命中的優勢
          │
          ▼
加總各詞貢獻 → 依分數由高到低排序 → 回傳前 K 筆
```

這是簡化流程。實際候選集合還會受到查詢的 AND／OR 條件、欄位與篩選條件影響。中文斷詞及查詢與文件的分析設定，也會直接影響命中。

## 2. 三個因素，各自解決什麼問題？

```text
              單一查詢詞的分數貢獻
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
       IDF：辨識力             調整後的詞頻
       看整個文件集合                 │
                             ┌───────┴───────┐
                             ▼               ▼
                         出現次數         文件長度
                         增益會飽和       相對平均長度
```

| 因素           | 直覺                                 | 注意事項                       |
| -------------- | ------------------------------------ | ------------------------------ |
| 逆文件頻率 IDF | 到處都有的詞，較難區分文件           | 稀有程度以目前文件集合為準     |
| 詞頻 TF        | 多次提及查詢詞，通常比偶爾提到更相關 | 重複 10 倍，不會得到 10 倍分數 |
| 長度正規化     | 長篇文章比較容易碰巧包含查詢詞       | 不是一律讓短文件勝出           |

## 3. 用數字看「詞頻飽和」

假設只搜尋一個詞，所有文件長度都等於平均長度，設定 `k1 = 1.2`。先不乘上 IDF，只比較詞頻因子：

```text
詞頻因子 = f × 2.2 / (f + 1.2)

出現次數 f     詞頻因子       長條（同一尺度，取近似長度）
  1             1.000        ██████████
  2             1.375        ██████████████
  5             1.774        ██████████████████
 10             1.964        ████████████████████
 20             2.075        █████████████████████
 趨近無限       趨近 2.200   ────────────────────── 上限
```

**重點：出現次數從 2 次變成 20 次，詞頻因子並沒有增加十倍。** 上限 2.2 僅適用於這裡的詞頻因子與參數設定，不是整份文件的 BM25 分數上限。

## 4. 用同一個詞，比較三份文件

教學用假設：`k1 = 1.2`、`b = 0.75`、平均文件長度 `avgdl = 100` 詞元，並將查詢詞的 `IDF` 固定為 `1`，方便單獨比較詞頻與長度的影響。

| 文件        | 長度（詞元） | 查詢詞出現次數 | BM25 分數（約） |
| ----------- | -----------: | -------------: | --------------: |
| A：短文件   |           50 |              2 |           1.600 |
| B：長文件   |          200 |              2 |           1.073 |
| C：多次提及 |          100 |              5 |           1.774 |

```text
排名    文件    分數
 1       C     ██████████████████  1.774
 2       A     ████████████████    1.600
 3       B     ███████████         1.073
```

- **A 對 B：**詞頻相同，較短的 A 得分較高。
- **C 對 A：**C 雖然較長，但更多次命中，仍可能勝出。
- 這是明確假設下的示例，不是真實搜尋引擎的實測結果；不能只看標題或篇幅就斷言排名。

## 5. 對照公式

以下為常見的 BM25 形式，以每個相異查詢詞計算一次貢獻：

```text
score(D, Q) = Σ IDF(t) × TF_adjusted(t, D)
             t∈Q

                               f(t,D) × (k1 + 1)
TF_adjusted(t,D) = ─────────────────────────────────────────
                   f(t,D) + k1 × (1 − b + b × |D| / avgdl)
```

| 符號              | 意義                             |
| ----------------- | -------------------------------- |
| `D`、`Q`、`t`     | 文件、查詢詞集合、其中一個查詢詞 |
| `f(t,D)`          | 詞 t 在文件 D 中出現幾次         |
| 文件長度、`avgdl` | 文件詞元數、文件集合的平均詞元數 |
| `k1`              | 控制詞頻飽和；常見約 1.2～2.0    |
| `b`               | 控制長度正規化；常見為 0.75      |

`b = 0` 時不做長度正規化；`b = 1` 時完整套用公式中的長度比例調整。在固定文件長度、`k1 > 0` 的一般設定下，較大的 `k1` 讓詞頻增益較晚飽和。

一種常見、保持非負的 IDF 寫法如下；不同實作可能採用其他變體：

```text
IDF(t) = ln(1 + (N − n(t) + 0.5) / (n(t) + 0.5))

N    = 文件總數
n(t) = 包含詞 t 的文件數（不是該詞的總出現次數）
```

**分數主要用於同一查詢與搜尋設定下的結果排序，不存在通用的「超過幾分就相關」門檻。**

## 6. 為什麼常與向量搜尋搭配？

```text
                       使用者查詢
                           │
              ┌────────────┴────────────┐
              ▼                         ▼
         BM25 詞彙搜尋              向量搜尋
         關鍵字吻合                  語意接近
         型號／錯誤代碼              同義改寫／概念
              │                         │
              └────────────┬────────────┘
                           ▼
                   排名融合，例如 RRF
                           │
                           ▼
                 可選：Reranker 重排序
                           │
                           ▼
                 搜尋結果／RAG 參考片段
```

- **BM25：**擅長找出包含明確詞彙的文件；未命中的同義說法可能漏掉，除非另外設定同義詞展開等分析機制。
- **向量搜尋：**擅長找到語意接近的說法，但不能保證符合精確的型號或數值條件。
- **混合搜尋：**兩者互補，但仍需依實際資料評估效果，不保證一定更好。
- **RRF（Reciprocal Rank Fusion）：**以排名融合結果，避免直接相加尺度不同的原始分數。

> 一句話記住：BM25 = 詞彙稀有度 × 經詞頻飽和與文件長度調整的命中貢獻，再對查詢詞加總。
